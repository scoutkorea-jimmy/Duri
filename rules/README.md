# rules/ — 두리손잡고 개발 규칙 인덱스

이 폴더가 **이 저장소의 모든 개발 규칙**을 담고 있습니다.
루트에는 [CLAUDE.md](../CLAUDE.md) 하나만 두고, 규칙 본문은 전부 여기에 있습니다.

---

## 읽는 순서

작업 종류와 상관없이 **① → ② → ③ 은 항상** 거칩니다.

1. **[HANDOFF.md](HANDOFF.md)** — ⛔ **무조건 가장 먼저.** 진행 중·보류 작업을 확인하고,
   **받은 지시를 코드에 손대기 전에 항목으로 등록**합니다.
2. **[00-core.md](00-core.md)** — 절대 규칙(어기면 화면·배포가 깨짐) + 표준 작업 흐름
3. **[WORKLOG.md](WORKLOG.md)** — 과거에 같은 지시가 있었는지, 실패한 적이 있는지 확인

그다음 **작업 종류에 맞는 파일만** 골라 읽습니다.

| 하려는 일 | 읽을 파일 |
|---|---|
| JS·HTML 구조를 고친다 / 새 페이지를 만든다 | [10-structure.md](10-structure.md) |
| 색·간격·컴포넌트 등 **보이는 것**을 바꾼다 | [20-design.md](20-design.md) |
| 메뉴·공지글·갤러리 사진·파트너 로고를 추가한다 | [30-content.md](30-content.md) |
| 커밋 전에 검증한다 / 배포 상태를 확인한다 | [40-verify.md](40-verify.md) |
| 다음에 뭘 할지 정한다 / 알려진 결함을 확인한다 | [50-roadmap.md](50-roadmap.md) |

작업이 끝나면 **[WORKLOG.md](WORKLOG.md)에 결과와 사유를 기록**하고 **[HANDOFF.md](HANDOFF.md) 항목을 종료로 옮깁니다.** 둘 다 선택이 아닙니다.

> **HANDOFF = 지금 진행 중인 것 / WORKLOG = 끝난 것.** 역할을 섞지 마세요.

## 규칙을 고칠 때

- 규칙과 코드가 다르면 **코드가 정답**입니다. 발견 즉시 규칙 파일을 코드에 맞추세요.
- 새 규칙은 주제에 맞는 기존 파일에 추가합니다. 새 파일은 기존 6개로 도저히 분류가 안 될 때만 만들고, 만들면 **이 인덱스와 [CLAUDE.md](../CLAUDE.md)의 지도 표를 같이 갱신**합니다.
- 규칙 변경도 [WORKLOG.md](WORKLOG.md)에 기록 대상입니다.

# HANDOFF — 진행 중 작업 (가장 먼저 읽는 문서)

> **⛔ 이 저장소에서 일을 시작할 때 가장 먼저 여는 문서입니다.**
> 지시를 받으면 **코드를 건드리기 전에 이 파일에 먼저 작업을 등록**하고, 진행하면서 갱신합니다.
> 완료된 작업의 결과·사유는 [WORKLOG.md](WORKLOG.md)로 옮깁니다. 규칙 인덱스는 [README.md](README.md).

---

## 이 문서의 규칙

**HANDOFF = 지금 진행 중인 것 / WORKLOG = 끝난 것.** 역할을 섞지 마세요.

1. **지시를 받은 즉시**, 아직 아무것도 조사·수정하기 전에 아래 "진행 중" 에 항목을 만듭니다.
   지시 원문, 목표, 성공 판단 기준을 먼저 적습니다. **비어 있는 항목이라도 만드는 것이 규칙입니다.**
2. 작업하면서 **"어디까지 됐는지"를 계속 갱신**합니다. 다음 세션이 맥락 없이 읽어도 이어받을 수 있어야 합니다.
3. 작업이 끝나면
   - [WORKLOG.md](WORKLOG.md)에 결과 + **성공 사유 / 실패 사유**를 기록하고
   - 이 문서의 항목을 **"최근 종료"** 로 옮깁니다(3건까지만 남기고 그 이상은 지웁니다).
4. 막히면 항목 상태를 `⏸ 보류`로 바꾸고 **무엇이 막았는지, 무엇이 있으면 풀리는지**를 적습니다.
   보류된 항목은 지우지 않습니다.
5. 사용자가 위험을 고지받고도 진행을 지시했다면 해당 항목에 **리스크 감수 기록**을 남깁니다.

### 항목 틀

```markdown
### [상태] 한 줄 제목
- **지시**: 사용자 원문(요지)
- **목표 / 성공 기준**: 무엇이 되면 끝인가
- **진행**:
  - [x] 끝난 단계
  - [ ] ← 지금 여기. 구체적으로
- **다음 한 수**: 복사해 실행할 수 있는 형태로
- **건드린 것**: 경로 / 한 일 / 되돌리는 법
- **막힌 것 · 확인 필요**: 사용자에게 물어야 할 것
```

상태: `▶ 진행 중` · `⏸ 보류` · `✅ 종료(WORKLOG 기록 완료)`

## 진행 중

### ▶ 홈페이지 전반 기능 개선 (다음 단계 대기)
- **지시**: "홈페이지의 전반적인 기능 개선을 진행할 건데, 먼저 폴더를 개선할 거야." — 폴더·규칙 정비가 1단계였고, 기능 개선 본체가 남아 있음.
- **목표 / 성공 기준**: [50-roadmap.md](50-roadmap.md)의 우선순위대로 처리. 각 묶음마다 검증 통과 + 배포 성공 + WORKLOG 기록.
- **진행**:
  - [x] 개발 상태 전수 점검 → [50-roadmap.md](50-roadmap.md)
  - [x] 규칙 폴더 재구성(`rules/`), 접근성 버그 2건, 진입 게이트 + 사이트 전환 바
  - [x] 시각 톤 절제(모션 전면 제거) + KWCAG 2.2 준수 — 자동 검사 23건 통과
  - [ ] ← **지금 여기.** 다음 묶음 착수 대기. 권장 순서는 아래 "다음 한 수"
- **다음 한 수** (사용자 지시 대기 — 임의로 시작하지 말 것):
  1. **C1~C4 + C6 · SEO/공유** — 15페이지 `meta description`·`og:*`·`canonical` + `sitemap.xml`·`robots.txt`·`404.html`. 정적 파일 추가만이라 비용 대비 효과 최대
  2. **B10~B12 · 접근성 수동 점검** — 화면 낭독기(VoiceOver) 실사용, 그라데이션 배경 위 텍스트 판독성, 확대 200%. 자동 검사가 못 보는 구간
  3. **D1~D2 · 성능** — Pretendard `@import` → `preload`, 인라인 `<style>` 통합
  4. **A3 · 실제 사진·로고 확보** (외부 의존 — 자산이 들어와야 시작 가능)
  5. **A1·A2·E3 · 서버리스 백엔드** — 게시판·폼·인증을 한 번에
  6. **A4 · 직업재활센터 사이트 본체** — 콘텐츠 확정 후 페이지 세트 + `NAV_REHAB`
- **건드린 것**: 아래 "최근 종료" 3건 참조
- **막힌 것 · 확인 필요**:
  - **A3(사진·로고)** 은 자산이 없어 시작 불가. 사진·파트너 로고 파일을 받아야 함
  - **A4(직업재활센터 본체)** 는 센터 소개·프로그램 콘텐츠가 확정되어야 시작 가능
  - **A1(서버리스 게시판)** 은 어느 백엔드로 갈지(Cloudflare / Firebase / Supabase) 결정 필요

## 최근 종료

### ✅ 진입 게이트로 되돌아갈 수단 신설 (2026-08-17)
- **문제**: 게이트가 `localStorage["duri.site.v1"]` 가 비었을 때만 떠서, 한 번 선택하면 개발자도구로 값을 지우는 것 외에 다시 볼 방법이 없었음(설계 누락, 사용자 지적).
- 전 페이지 푸터에 **"처음 선택 화면 다시 보기"**(`.foot-reset` → `index.html?gate=1`). 홈에서는 이동 없이 즉시 열림.
- `?gate=1` / `#gate` 직접 진입 지원. **다시 열린 게이트만** 닫기 버튼 + ESC 로 닫히고 기존 선택 유지.
- 선택 후 `history.replaceState` 로 `?gate=1` 정리.
- 검증: `verify-headless.mjs` 에 10건 추가 → **50건 전부 통과**. 접근성 23건 유지.

### ✅ 시각 톤 절제 + KWCAG 2.2 준수 (2026-08-17)
- **결정**: 장식(그라데이션·색면)은 유지, **모션은 전면 제거** / 로고 마퀴 → 정적 그리드 / 게이트 단색·확대 없음.
- 접근성: 건너뛰기 링크, `<main>` 15페이지, 폼 레이블 21개 결속, 장식 SVG 48개 `aria-hidden`,
  대비 위반 6종 해결, 컨트롤 44×44, 대화상자 초점 관리, `radiogroup` 시맨틱, 오류 `role="alert"`.
- 부수 발견: **`.cta-band`/`.cta-cards`/`.cta-tile` 이 정의 없이 쓰여 흰 글자가 흰 배경에 렌더**되고 있었음 → 정의 추가.
  **`family.html` 의 `.acct` 가 헤더 계정 컨트롤(`#acct`)까지 덮어쓰던 충돌** → `.donate-acct` 로 분리.
- 검증: `tools/verify-a11y.mjs` 23건 + `verify-headless.mjs` 40건 = **63건 전부 통과**. 사유는 [WORKLOG.md](WORKLOG.md).

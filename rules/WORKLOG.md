# WORKLOG — 지시·개선 이력

> **이 파일은 작업 시작과 종료 시 반드시 열립니다.** 기록하지 않은 작업은 완료된 것으로 보지 않습니다.
> 규칙 인덱스는 [README.md](README.md), 작업 흐름은 [00-core.md](00-core.md).

---

## 기록 규칙

- **최신 항목을 맨 위에** 씁니다(역순).
- 한 항목 = 한 지시. 하나의 지시가 여러 작업으로 갈라지면 하위 항목으로 씁니다.
- **결과는 ✅ 성공 / ⚠️ 부분 성공 / ❌ 실패 / ⏸ 보류 넷 중 하나**로 명시합니다.
- **사유는 반드시 씁니다.**
  - ✅ 성공 → **무엇을 근거로 성공이라 판정했는지**(검증 결과). "잘 됐다"는 사유가 아닙니다.
  - ❌ 실패 / ⏸ 보류 → **왜 못 했는지, 무엇이 막았는지, 어떤 조건이 갖춰지면 가능한지.**
- **검증** 칸에는 실제로 돌린 명령과 그 출력 요지를 씁니다. 안 돌렸으면 "미검증"이라고 적습니다. 추측을 검증으로 적지 않습니다.
- 지시를 그대로 수행하지 않고 범위를 넓히거나 좁혔다면 **그 사실과 이유를 반드시 적습니다.**

### 항목 틀

```markdown
## YYYY-MM-DD · 한 줄 제목

- **지시**: 사용자가 실제로 한 말(요지)
- **한 일**:
  - 구체적 변경 1 (`파일경로`)
- **결과**: ✅ 성공
- **사유**: 성공/실패로 판정한 근거
- **검증**: 실행한 명령과 출력 요지
- **범위 조정**: 지시와 다르게 한 부분과 그 이유 (없으면 생략)
- **커밋**: `해시`
```
